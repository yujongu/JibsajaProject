The block has no width. It has a rule.

A hard-coded 56px is wrong the moment someone raises their phone's text size — the label grows, the block doesn't, and the text clips. So don't set a width: measure the widest label at the current text scale and let that be the width, plus a small pad on each side. Change the text scale in the bar and watch the block follow.

How this lands in Flutter

The browser measures with a hidden span; Flutter measures with TextPainter. Same rule, and it re-runs whenever the platform text scale changes because MediaQuery rebuilds the widget for you.

Measure the set, not the row

Lay out all sixteen labels once for the current scaler, keep the widest, and cache it keyed on that scaler — it's sixteen text layouts on a scale change, not per row, per frame. 

double blockWidth(BuildContext context) {
  final scaler = MediaQuery.textScalerOf(context);
  final style = TextStyle(fontSize: 9, fontWeight: FontWeight.w700);
  var w = 0.0;
  for (final label in knownBlockLabels) {
    final tp = TextPainter(
      text: TextSpan(text: label.toUpperCase(), style: style),
      textScaler: scaler,
      textDirection: TextDirection.ltr,
    )..layout();
    w = max(w, tp.width);
  }
  return w + 2 * 8; // the side pad
}

Unknown types must not widen it

A row whose sheet Type the app doesn't recognise shows the sheet's own wording, which can be any length. Measure only the sixteen known labels; let an unrecognised one ellipsize inside the block it's given.

Otherwise a single stray value like "Reimbursement adjustment" in one cell widens the block on every row of the month.

Cap it before it eats the row

At 160% the block is roughly 78px and the description is visibly squeezed. Clamp the measured width to about a third of the card — past that, keep the icon, drop the label to the body as a coloured kicker, and let the description have the room back.

Padding stays fixed at every scale, which is what Flutter's textScaler does too — it scales type, never EdgeInsets.
